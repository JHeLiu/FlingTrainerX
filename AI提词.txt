帮我写一个构建打包脚本，需求如下。

【项目背景】
一个基于 WPF 桌面项目，需要在项目根目录的 .pro 文件夹中编写一个可双击执行的构建打包脚本（.bat 或 .ps1 均可，你选合适的）。

【脚本存放位置】
- 放在：项目根目录.pro/ 目录下，切记是解决方面同级目录
- 脚本必须能双击直接运行，运行失败时要暂停窗口（不能一闪而过）
- 脚本命名 publish

【交互流程】
1. 双击脚本后，先显示上一版本的版本号（从 .pro 目录下的版本记录文件中读取；若没有记录则显示"无"）
2. 提示用户输入新版本号，格式强制校验为 x.x.x（如 1.2.3），不合法则重新输入
3. 用户确认后开始执行构建 + 打包流程
4. 整个流程只输出简要的流程节点（例如： 开始编译…  编译完成 开始打包… 打包完成），要输出进度条跟执行时间

【构建步骤】
构建参数固定为：
dotnet publish -c Release -f net10.0-windows -r win-x64 --self-contained true -p:PublishSingleFile=true -p:PublishReadyToRun=true -o "<输出目录>"

对应需求：独立部署版本 / win-x64 / 生产单个文件 / 启用 ReadyToRun 编译。

输出目录规则：
- 输出到项目根目录 .pro/<新版本号>/ 目录下（直接就是版本号目录）
- .pro/<新版本号>/publish/里面是.NET发布的文件内容
- 重要：每次构建时不要删除 .pro 下已有的历史版本目录，只新增本次版本目录，历史构建文件全部保留

【打包步骤 - 使用 NSIS】
- NSIS，已经设置了全局变量，直接用命令就行 
- 构建完成后调用 NSIS 对 .pro/<新版本号>/ 下的产物进行打包
- 安装界面要求：有桌面快捷方式、添加到快速启动栏选项这些常规的，可以用户自己选择安装那个位置，要记住用户之前安装的位置，好方便下次安装自动更新
- 不需要任何免责声明页面
- 安装包命名规则：<软件名>-<版本号>.exe
- 软件名从脚本内配置读取（脚本顶部留一个变量方便修改）
- 安装包也输出到 .pro/<新版本号>/ 目录下

【交付物】
请一次性输出以下内容：
1. 完整的主脚本文件（可双击执行，包含版本号读取 / 输入 / 校验 / 记录逻辑）
2. 完整的 NSIS 脚本文件

【风格要求】
- 脚本注释清晰，所有可配置变量集中在顶部便于修改
- 主流程输出简洁，只用步骤编号 + 一句话描述
- 任何一步失败都要明确提示失败原因，并暂停窗口等待用户按键
