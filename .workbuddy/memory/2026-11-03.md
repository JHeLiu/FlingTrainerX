# 2026-11-03

## 卡片封面改用官网头图（featured media）

用户提出「首页卡片是不是在 `article` / `post-details-thumb` 下，解析这个节点是不是什么都有」，
核实后确认属实，但最终没有改走 HTML 列表，而是给 REST 接口加了 `_embed=wp:featuredmedia`。

**官网页面的真实结构**（实测 `curl https://flingtrainer.com/`）：

- 一个 `<article>` 内含：`.post-details-thumb > a > img`（封面）、`.post-details-day/month/year`
  （拆成三个 div 的日期）、`h2.post-title > a`（标题 + 详情链接）、`div.entry`
  （`30 Options · Game Version: … · Last Updated: …`）、`.post-meta`（作者 / 分类 / 评论数）
- **首页一页只有 15 条**，REST 接口 `per_page=24` 是 24 条；接口 `X-WP-TotalPages: 32`
- 卡片日期取的是 `modified`（最后更新），不是 `date`：`Europa Universalis V` 发布 2025-11-04、
  修改 2026-10-31，卡片显示 `31 Oct 2026`
- 首页顺序与 `orderby=modified&order=desc` 完全一致（逐条比对过前 15 条）
- 详情页的 `post-details-thumb` 是**作者头像**（gravatar），和列表页同名不同义
- 详情页下载表容器是 `div.download-attachments`，表格类名 `da-attachments-table`（不是 `table.download-attachments`）

**取舍结论**：列表继续走接口，因为 (a) 15 条 vs 24 条，改 HTML 会让翻页次数多 60%；
(b) 接口 `content` 里带完整选项分组，弹框打开即可显示，改 HTML 后每次点卡片都要再请求详情页。
只有封面从 `_embed` 拿。

**收益（实测）**：
- 正文首图 `1-15.png` 是**修改器界面截图**，1926×1157 / **779 KB**，之前被当作卡片封面
- 官网头图 `header.jpg` 是**游戏艺术图**，`stylizer-medium` 档 520×292 / 约 150 KB，小 14 倍
- 24 条带 `_embed` 的整页 JSON：42 KB → **50.7 KB**（+8.6 KB）
- 24/24 都有 `stylizer-medium`、`stylizer-large`（720×404）两档，尺寸集合一致
- 官网自己引的是 `header-200x200.jpg`（方形裁切），原图 `header.jpg` 只有 460×215；
  去掉 `-200x200` 后缀取原图，15/15 都返回 200

## 踩坑

- `RowDefinition Height="{DynamicResource X}"`：DynamicResource 不做类型转换，
  资源必须是 `GridLength`，不能是 `Double`。
- 网络图 `CacheOption.OnLoad` 会在调用线程同步等下完整张图（卡 UI）；
  卡片/列表必须用 `OnDemand`，只有在后台线程里才可以用 `OnLoad`。
- 介绍图下载未完成时先别把容器设为 Visible，否则会空出一大块；改成挂
  `DownloadCompleted` 再显示（本项目里 `IntroHost` 默认 Collapsed）。
- `rm -rf "$LOCALAPPDATA/FlingTrainerX/images"` 在应用运行时静默失败，清缓存要先关进程。

   `CloneCurrentValue()` 一份——模板里的 Freezable 可能被 WPF 冻结，直接动画会抛异常。

3. **最大化不是全屏的真正原因**：`WindowStyle=None + WindowChrome` 会把窗口往外撑一圈隐形边框
   （本机 96 DPI 下 7px）。`MaxWidth/MaxHeight` 卡在工作区大小时窗口只到 1920×1032 且内容内缩 7px
   （右边下边漏缝）；放开上限又会被 WPF 撑到 1934×1072，内容 1058 高、底部 26px 伸进任务栏被裁。

   按 `GetMonitorInfo` 工作区反推 `ptMaxSize/ptMaxPosition` → 最大化后正好 0,0,1920×1032。
   接管后系统不再补默认值，`ptMinTrackSize`/`ptMaxTrackSize` 必须自己填，否则 `MoveWindow`
   会把窗口压成最小尺寸（1100×680）。
4. **最大化时切直角**：`DWMWCP_DONOTROUND` + `Shell.CornerRadius=0` + `BorderThickness=0`，
   `StateChanged` 里统一处理（双吉标题栏、Win+↑、按钮都走这里），图标同步 `\uE923`/`\uE922`。
5. **跨屏 DPI**：`ApplyWindowBounds` 改用 `GetDpiForWindow`（和 `MonitorFromWindow` 同一套），
   `OnDpiChanged` 里改成 `DispatcherPriority.Background` 延后重算，否则会拿「新 DPI + 旧显示器」
   算出 1106×679 这种偏小尺寸。
6. 卡片去掉 `ToolTip`（标题就在图下面，弹出来反而挡住放大效果）；水印字母改成常驻在封面之下，
   图没下完/下载失败时不再是空白色块。

## 首页优化（第三轮）

1. **去掉「共 N 款 · N 个选项」**：官网接口只给分页总数（`X-WP-Total=767`，会随更新变），

   队列页原本靠这枚统计显示 `SummaryText`，改挂到 `SectionSubtitle`。
2. **翻页一次只加载一页**：`CardList_ScrollChanged` 只认 `VerticalChange > 0`
   （旧代码把 `ViewportHeightChange` 也算进去，插完一页立刻又满足「到底」→ 连锁加载）。
   新增 `_lastTriggerOffset`：同一次滚动只触发一次，必须再往下滚过上次触发点才会再要。
   滚轮贴在底部时 Offset 不变、没有 ScrollChanged，`PreviewMouseWheel` 里用 `userGesture:true`
   绕过位置判定补一刀。`_loadingMore` 仍是硬闸：上一页没回来，滚什么都没用。
3. **翻页进度落盘**：`dbs\library.page` 一个数字（`TrainerDataService.Load/SavePageCursor`）。
   缓存表里只有卡片没有页码，不记的话每次启动都从第 2 页重翻，全是重复内容、滚到底也看不到新东西。
   缓存为空时重置为 1。另外翻页循环里整页都是已有内容会顺延下一页（最多 5 次）。
4. **虚拟滚动实测**（临时探针，验完已删）：`ListBox` 一行 = 一个 item，`VirtualizationMode=Recycling`
   + `ScrollUnit=Pixel` + `CacheLength=1 屏`；384 款 / 77 行时视觉树里始终 8~14 行（40~70 张卡），
   滚到底也不增加。探针统计卡片要按 `Button.Tag is TrainerItem` 数，否则会把收藏的删除按钮算进去。
5. **内存一直涨的真凶是图片不是容器**：`NetImages` 原来是 `ConcurrentDictionary` 无上限缓存，
   一张 520×292 封面解码后 0.6 MB，几百款就是几百兆。改成 LRU（160 张 / 96 MB，`LinkedList`+字典，
   按 `PixelWidth*PixelHeight*4` 估算字节，取不到时按 1 MB 记），滚过去的图释放给 GC，
   再回来从本地 `f\<id>\cover.jpg` 重新解码。实测缓存停在上限后不再增长，GC 后工作集回落。
6. 探针思路：临时在 `CaptureTourAsync` 末尾加 `ProbeVirtualScrollAsync`，写 `probe.txt`
   （行数/realize 行数/卡片数/页码/工作集/图片缓存），用 `ScrollToVerticalOffset` 逐屏滚，
   验证「一页一滚」与容器数量恒定；验完**整段删掉**并 grep 确认无残留。
